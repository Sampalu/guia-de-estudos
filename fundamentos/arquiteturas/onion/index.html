Onion Architecture (2008)

Arquitetura Onion (Cebola)
Tags:
  • Arquiteturas
Categories:
  • Fundamentos

  3 minute read  

A Arquitetura Onion foi criada com o objetivo principal de garantir que a lógica de negócio seja completamente independente de detalhes de infraestrutura e frameworks, promovendo uma estrutura mais modular, flexível e testável.

Ela busca evitar o alto acoplamento entre as camadas da aplicação, tornando a lógica de negócio reutilizável e resistente a mudanças tecnológicas.

Como a Arquitetura Onion Resolve Problemas Comuns?

- Dependência Inversa: Em arquiteturas tradicionais, a lógica de negócio depende da infraestrutura (ex.: ORM, APIs externas). Na Arquitetura Onion, essa relação é invertida: a infraestrutura é que depende do domínio, garantindo independência.

- Código mais sustentável: Como a lógica de negócio não está misturada com detalhes técnicos, o código se torna mais modular e fácil de evoluir.

- Facilidade de testes: Como a camada de aplicação depende apenas de interfaces, podemos usar mocks para testar a lógica sem precisar de um banco de dados ou serviços externos.

Estrutura da Arquitetura Onion

A Arquitetura Onion é representada por camadas concêntricas, onde a lógica de negócio está no centro e as dependências externas ficam na periferia.




1. Domain (Domínio) → Contém as entidades e regras de negócio puras.
2. Application (Casos de Uso) → Contém serviços e interfaces que orquestram a lógica de negócio.
3. Infrastructure (Infraestrutura) → Implementa interfaces, como repositórios e integrações com banco de dados.
4. Presentation (Interface de Usuário) → Pode ser API, MVC, Console App, etc., responsável por interagir com o usuário.

Exemplo Prático em C#

1️. Camada Core (Domínio)

public class Customer
{
    public int Id { get; set; }
    public string Name { get; set; }
    public string Email { get; set; }
}

public interface ICustomerRepository
{
    Customer GetCustomerById(int id);
    void AddCustomer(Customer customer);
}

2️. Camada Application (Casos de Uso)

public class CustomerService
{
    private readonly ICustomerRepository _customerRepository;

    public CustomerService(ICustomerRepository customerRepository)
    {
        _customerRepository = customerRepository;
    }

    public void RegisterCustomer(string name, string email)
    {
        var customer = new Customer { Name = name, Email = email };
        _customerRepository.AddCustomer(customer);
    }
}

3. Camada Infrastructure (Infraestrutura - Implementação do Repositório)

public class CustomerRepository : ICustomerRepository
{
    private readonly List<Customer> _customers = new List<Customer>();

    public Customer GetCustomerById(int id) => _customers.FirstOrDefault(c => c.Id == id);
    public void AddCustomer(Customer customer) => _customers.Add(customer);
}

4️. Camada Presentation (Interface de Usuário - API Controller)

[ApiController]
[Route("api/customers")]
public class CustomerController : ControllerBase
{
    private readonly CustomerService _customerService;

    public CustomerController(CustomerService customerService)
    {
        _customerService = customerService;
    }

    [HttpPost]
    public IActionResult RegisterCustomer([FromBody] Customer customer)
    {
        _customerService.RegisterCustomer(customer.Name, customer.Email);
        return Ok("Customer registered successfully");
    }
}

Conclusão

✅ Baixo Acoplamento – A camada de domínio não depende de infraestrutura ou frameworks específicos.
✅ Alta Testabilidade – Como a lógica de negócio está isolada, fica mais fácil escrever testes unitários.
✅ Facilidade de Manutenção – A separação em camadas permite modificar partes do sistema sem afetar outras.
✅ Flexibilidade Tecnológica – Tecnologias externas, como banco de dados e frameworks, podem ser substituídas sem afetar o core da aplicação.

A Arquitetura Onion ajuda a criar sistemas bem estruturados, desacoplados e fáceis de testar. Ao manter a lógica de negócio isolada, facilita a manutenção e a evolução do software sem estar preso a frameworks ou tecnologias específicas.
