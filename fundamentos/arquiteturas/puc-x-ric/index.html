PUC x RIC

Arquitetura PUC (Processing Unit Centered) x RIC (Resource Interaction Centered)
Tags:
  • Arquiteturas
  • Api Gateway
Categories:
  • Fundamentos

  4 minute read  

Se uma vaga de emprego exige conhecimento sobre arquitetura PUC e RIC, significa que a empresa espera que você tenha experiência com diferentes formas de organizar sistemas distribuídos. Para se preparar, você deve entender como essas arquiteturas impactam o design, escalabilidade e manutenção de sistemas. Aqui estão os principais tópicos para estudar:

Conceitos Fundamentais de PUC e RIC

Em Tecnologia da Informação, PUC (Processing Unit Centered) e RIC (Resource Interaction Centered) são conceitos de arquitetura voltados para a organização e estruturação de sistemas distribuídos.

  • Revisar as diferenças entre PUC (Processing Unit Centered) e RIC (Resource Interaction Centered).
  • Entender quando usar cada abordagem, dependendo do problema a ser resolvido.
  • Comparar com outras arquiteturas, como Monolítico, Microservices e Serverless.

Arquitetura PUC (Processing Unit Centered)

A abordagem PUC enfatiza o papel das unidades de processamento (como servidores, VMs, containers) como elementos centrais da arquitetura. Cada unidade de processamento é projetada para executar uma determinada lógica de aplicação e processar requisições, utilizando recursos conforme necessário.

  • Os nós de processamento são o foco principal.
  • Estudar arquitetura tradicional de microservices, onde cada serviço é responsável por sua própria lógica e persistência de dados.
  • Modelos de escalabilidade baseados em horizontal scaling (adicionar mais instâncias de serviços) e vertical scaling (aumentar capacidade do servidor).
  • O sistema é projetado com base na capacidade e escalabilidade dessas unidades.
  • Normalmente, cada nó gerencia seus próprios recursos locais e comunicação.
  • Tecnologias associadas:
    • Docker e Kubernetes (para gerenciamento de containers e escalabilidade).
    • Spring Boot, .NET Core, Express.js (frameworks para microservices).
    • Banco de dados relacionais (PostgreSQL, MySQL, SQL Server) e como são usados em arquiteturas PUC.

Arquitetura RIC (Resource Interaction Centered)

Já a abordagem RIC inverte essa lógica, enfatizando a interação entre os recursos e sua orquestração, em vez de focar nas unidades de processamento individuais. A ideia é que os sistemas sejam modelados com base na maneira como os recursos interagem, tornando-os mais escaláveis e flexíveis.

  • O foco está na coordenação de recursos em vez das unidades de processamento.
  • Estudar Modelos baseados em atores (Actor Model), onde os componentes interagem por mensagens e eventos.
  • Arquitetura orientada a eventos (Event-Driven Architecture) e como ela se diferencia dos microservices tradicionais.
  • Permite maior elasticidade e resiliência, pois os recursos podem ser distribuídos e reutilizados de maneira mais eficiente.
  • Tecnologias associadas:
    • Microsoft Orleans (um framework que implementa o modelo de atores).
    • Akka.NET (outra alternativa para sistemas distribuídos baseados em atores).
    • Kafka, RabbitMQ, AWS SQS (mensageria para sistemas baseados em eventos).
    • Banco de dados NoSQL (Cassandra, DynamoDB, CosmosDB) para escalabilidade.

Práticas e Casos de Uso

  • Comparação entre PUC e RIC na prática: quando um modelo faz mais sentido que o outro?
  • Projetar um sistema de exemplo usando ambas as abordagens.
  • Conhecer Cloud Computing (AWS, Azure, GCP), pois muitas empresas usam PUC e RIC para arquiteturas escaláveis na nuvem.
  • Ler sobre arquiteturas resilientes e distribuídas, como CQRS (Command Query Responsibility Segregation) e Event Sourcing, pois podem estar relacionadas a RIC.

Exercícios Práticos

  • Criar um sistema simples de microservices (arquitetura PUC) usando Docker, Kubernetes e um API Gateway.
  • Implementar um pequeno sistema baseado em eventos (arquitetura RIC), usando Microsoft Orleans ou RabbitMQ para comunicação entre componentes.
  • Estudar arquiteturas de sistemas que já usam essas abordagens, como Orleans (usado no Halo da Microsoft) ou Akka.NET (usado em sistemas financeiros e jogos online).

Se a vaga pede conhecimento nessas arquiteturas, é bem provável que a empresa trabalhe com sistemas distribuídos modernos, exigindo experiência com cloud, microservices, mensageria e escalabilidade. Focar nesses temas vai te preparar bem para a vaga!

Comparação entre PUC e RIC

CaracterísticaPUC (Processing Unit Centered)RIC (Resource Interaction Centered)
Foco principalUnidades de processamentoInteração entre recursos
EscalabilidadeLimitada pela unidade de processamentoAlta, baseada na interação de recursos
Arquitetura comumMicroservices tradicionaisEvent-driven, Actor Model
Exemplo de usoAplicações web tradicionaisSistemas distribuídos escaláveis

A escolha entre PUC e RIC depende do tipo de sistema que está sendo projetado. Sistemas tradicionais de TI frequentemente adotam PUC, enquanto arquiteturas mais modernas e escaláveis (como Microsoft Orleans) utilizam RIC.
