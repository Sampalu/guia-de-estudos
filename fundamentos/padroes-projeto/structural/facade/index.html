Facade - Structural (Estrutural)

Intenção

Facade (Fachada) é um padrão de projeto estrutural que tem a intenção de fornecer uma interface unificada para um conjunto de interfaces em um subsistema. Facade define uma interface de nível mais alto que torna o subsistema mais fácil de ser usado

Sobre o Facade

Em vídeo: https://www.youtube.com/watch?v=A7mNiaBACYs&list=PLbIBj8vQhvm0VY5YrMrafWaQY2EnJ3j8H&index=22

O Facade é o padrão mais simples de todos. Ele tem a intenção de facilitar a vida do código cliente ao criar um objeto de fachada para um sistema mais complexo.

Imagine ter que instanciar várias classes, passar objetos como parâmetro de outros objetos, chamar vários métodos ou executar algorítmos apenas para iniciar um sistema. O Facade ajudará você a não poluir o código cliente com todo esse código. Ele visa fornecer uma interface muito mais simples e unificada em um objeto que o cliente pode simplesmente chamar métodos e obter o comportamento desejado.

Pense no Facade como uma pessoa que atende telefones em um call center cheio de setores. O foco dessa pessoa é coletar informações com o cliente para saber para qual setor direcionar a ligação. O Facade é simples assim.

É importante ressaltar que o Facade não tem a intenção de ocultar nada do código cliente, a ideia é simplesmente facilitar o uso do sistema. O cliente ainda poderá usar os objetos do sistema diretamente se necessário.

Como esse padrão visa unificar coisas que poderiam estar separadas no sistema, é muito comum que a própria classe de fachada se torne uma “God Class” (uma classe faz tudo), isso quebra o SRP (princípio da responsabilidade única). Porém, ele também permite a criação de fachadas adicionais que podem ser usadas tanto por clientes quando por outras fachadas, o que ajuda a minimizar este problema.

Estrutura

Aplicabilidade

Use o padrão Facade quando:

  • você quer disponibilizar uma interface mais simples para um sistema complexo
  • você quer criar pontos de entrada para determinadas partes do sistema, como serviços externos, camadas da aplicação e objetos complexos dentro em determinadas partes do código

Ele é útil quando queremos esconder a complexidade de várias classes internas, fornecendo um único ponto de acesso a funcionalidades mais complexas.

Implementação

Aqui está um exemplo do Design Pattern Facade em C#.

Cenário do Exemplo

Imagine que estamos desenvolvendo um sistema de compra online. Esse sistema envolve múltiplos processos internos, como:

  • Validação de pagamento
  • Verificação de estoque
  • Processamento do pedido
  • Envio de notificação ao cliente

Ao invés de expor todas essas operações para o cliente, podemos criar uma Fachada (OrderFacade) que encapsula esses detalhes e fornece um método único para realizar a compra.

using System;

// Subsistema 1: Processamento de Pagamento
public class PaymentProcessor
{
    public bool ProcessPayment(string cardNumber, double amount)
    {
        Console.WriteLine($"💳 Processando pagamento de R$ {amount} para o cartão {cardNumber}");
        return true; // Supondo que o pagamento sempre é aprovado
    }
}

// Subsistema 2: Verificação de Estoque
public class InventorySystem
{
    public bool CheckStock(string productId, int quantity)
    {
        Console.WriteLine($"📦 Verificando estoque para o produto {productId} - Quantidade: {quantity}");
        return true; // Supondo que há estoque suficiente
    }
}

// Subsistema 3: Processamento do Pedido
public class OrderProcessor
{
    public void ProcessOrder(string productId, int quantity)
    {
        Console.WriteLine($"📜 Pedido processado: {quantity}x {productId}");
    }
}

// Subsistema 4: Notificação ao Cliente
public class NotificationService
{
    public void SendConfirmation(string email)
    {
        Console.WriteLine($"📧 E-mail de confirmação enviado para {email}");
    }
}

// 🔹 Fachada (Facade) que simplifica a interação com os subsistemas
public class OrderFacade
{
    private readonly PaymentProcessor _paymentProcessor;
    private readonly InventorySystem _inventorySystem;
    private readonly OrderProcessor _orderProcessor;
    private readonly NotificationService _notificationService;

    public OrderFacade()
    {
        _paymentProcessor = new PaymentProcessor();
        _inventorySystem = new InventorySystem();
        _orderProcessor = new OrderProcessor();
        _notificationService = new NotificationService();
    }

    public void PlaceOrder(string productId, int quantity, string cardNumber, double amount, string email)
    {
        Console.WriteLine("\n🔹 Iniciando processo de compra...");

        if (!_inventorySystem.CheckStock(productId, quantity))
        {
            Console.WriteLine("❌ Pedido cancelado: Produto fora de estoque.");
            return;
        }

        if (!_paymentProcessor.ProcessPayment(cardNumber, amount))
        {
            Console.WriteLine("❌ Pedido cancelado: Pagamento recusado.");
            return;
        }

        _orderProcessor.ProcessOrder(productId, quantity);
        _notificationService.SendConfirmation(email);

        Console.WriteLine("✅ Pedido concluído com sucesso!");
    }
}

// Programa principal
class Program
{
    static void Main()
    {
        // Criando a Fachada
        OrderFacade orderFacade = new OrderFacade();

        // Simulando um pedido
        orderFacade.PlaceOrder("Produto123", 2, "1234-5678-9012-3456", 299.99, "cliente@email.com");
    }
}

Explicação

  1. Criamos quatro classes que representam diferentes subsistemas:

    • PaymentProcessor: Processa o pagamento.
    • InventorySystem: Verifica o estoque.
    • OrderProcessor: Processa o pedido.
    • NotificationService: Envia e-mails de confirmação.

  2. Criamos uma classe OrderFacade que encapsula a complexidade dos subsistemas, oferecendo um método único PlaceOrder().

  3. No Main, usamos a OrderFacade para fazer uma compra sem precisar interagir diretamente com os subsistemas.

Saída esperada

🔹 Iniciando processo de compra...
📦 Verificando estoque para o produto Produto123 - Quantidade: 2
💳 Processando pagamento de R$ 299.99 para o cartão 1234-5678-9012-3456
📜 Pedido processado: 2x Produto123
📧 E-mail de confirmação enviado para cliente@email.com
✅ Pedido concluído com sucesso!

Consequências

O que é bom ou ruim no Facade:

Bom:

  • Isola o código complexo do código cliente
  • Reduz a complexidade - Facilita o uso do sistema ao esconder a lógica interna dos subsistemas
  • Facilita a manutenção ao permitir mudanças nos subsistemas sem afetar os clientes
  • Cria pontos de entrada para camadas da aplicação e serviços de terceiros
  • Melhora a reutilização, pois a fachada pode ser usada por diferentes partes do sistema

Ruim:

  • O objeto facade se torna facilmente uma “God class” (use fachadas adicionais se perceber que isso está ocorrendo no seu código)
