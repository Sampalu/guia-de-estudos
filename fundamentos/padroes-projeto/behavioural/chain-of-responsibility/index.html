Chain Of Responsibility - Behavioural (Comportamental)

Intenção

Evitar o acoplamento do remetente de uma solicitação ao seu destinatário, dando a mais de um objeto a chance de tratar a solicitação. Encadeia os objetos receptores e passa a solicitação ao longo da cadeia até que um objeto a trate

Sobre o Chain Of Responsibility

Em vídeo: https://www.youtube.com/watch?v=AdzLq9FVTXs&list=PLbIBj8vQhvm0VY5YrMrafWaQY2EnJ3j8H&index=37

O Chain of Responsibility (CoR) é um padrão comportamental que permite passar solicitações por uma cadeia de manipuladores até que um deles a processe.

Estrutura

Aplicabilidade

Use o Chain Of Responsibility quando:

  • seu sistema precisa processar uma requisição em várias etapas diferentes e você não quer criar uma ordem rígida para o processamento. O chain of responsibility permite que você altere a ordem dos objetos na cadeia facilmente (mesmo assim, mantendo uma ordem específica)
  • você quer aplicar o princípio da responsabilidade única para tratamento de dados da requisição. Cada objeto fica responsável por tratar apenas a parte que lhe couber
  • você quer permitir que os objetos responsáveis pelo tratamento de requisição possam variar em tempo de execução

Implementação

Aqui está um exemplo do Design Pattern Chain of Responsibility em C#.

Cenário do Exemplo

Vamos criar um sistema de suporte técnico onde pedidos de suporte são encaminhados por uma cadeia de manipuladores.

Regras de Negócio:

  • Se o problema for simples, o atendente resolve.
  • Se for moderado, o técnico resolve.
  • Se for grave, o gerente resolve.
  • Se ninguém puder resolver, retorna “Sem solução no momento”.
using System;

// Enum para definir os níveis de suporte
public enum SupportLevel
{
    Basic,      // Problemas simples
    Intermediate, // Problemas moderados
    Advanced    // Problemas graves
}

// Classe base para os manipuladores da cadeia
public abstract class SupportHandler
{
    protected SupportHandler? _nextHandler;  // Próximo na cadeia

    public void SetNextHandler(SupportHandler nextHandler)
    {
        _nextHandler = nextHandler;
    }

    public abstract void HandleRequest(SupportLevel level, string issue);
}

// Manipulador: Atendente de Suporte Básico
public class BasicSupport : SupportHandler
{
    public override void HandleRequest(SupportLevel level, string issue)
    {
        if (level == SupportLevel.Basic)
        {
            Console.WriteLine($"Atendente resolveu: {issue}");
        }
        else if (_nextHandler != null)
        {
            _nextHandler.HandleRequest(level, issue);
        }
        else
        {
            Console.WriteLine($"Sem solução para: {issue}");
        }
    }
}

// Manipulador: Técnico de Suporte Intermediário
public class IntermediateSupport : SupportHandler
{
    public override void HandleRequest(SupportLevel level, string issue)
    {
        if (level == SupportLevel.Intermediate)
        {
            Console.WriteLine($"Técnico resolveu: {issue}");
        }
        else if (_nextHandler != null)
        {
            _nextHandler.HandleRequest(level, issue);
        }
        else
        {
            Console.WriteLine($"Sem solução para: {issue}");
        }
    }
}

// Manipulador: Gerente de Suporte Avançado
public class AdvancedSupport : SupportHandler
{
    public override void HandleRequest(SupportLevel level, string issue)
    {
        if (level == SupportLevel.Advanced)
        {
            Console.WriteLine($"Gerente resolveu: {issue}");
        }
        else
        {
            Console.WriteLine($"Sem solução para: {issue}");
        }
    }
}

// Programa Principal
class Program
{
    static void Main()
    {
        // Criando os manipuladores
        SupportHandler basic = new BasicSupport();
        SupportHandler intermediate = new IntermediateSupport();
        SupportHandler advanced = new AdvancedSupport();

        // Configurando a cadeia de responsabilidade
        basic.SetNextHandler(intermediate);
        intermediate.SetNextHandler(advanced);

        // Testando o sistema de suporte
        basic.HandleRequest(SupportLevel.Basic, "Resetar senha");
        basic.HandleRequest(SupportLevel.Intermediate, "Erro ao conectar na rede");
        basic.HandleRequest(SupportLevel.Advanced, "Servidor caiu");
        basic.HandleRequest((SupportLevel)99, "Bug desconhecido");
    }
}

Explicação

  1. Criamos o SupportLevel, que representa os níveis de suporte.
  2. Criamos a classe base SupportHandler, que contém a lógica para passar a requisição ao próximo manipulador.
  3. Criamos os manipuladores concretos (BasicSupport, IntermediateSupport, AdvancedSupport) para lidar com os diferentes níveis de suporte.
  4. No Main(), criamos os manipuladores e os encadeamos.

Saída esperada

Atendente resolveu: Resetar senha
Técnico resolveu: Erro ao conectar na rede
Gerente resolveu: Servidor caiu
Sem solução para: Bug desconhecido

Consequências

O que é bom ou ruim no Chain Of Responsibility:

Bom:

  • Aplica o princípio da responsabilidade única (SRP)
  • Aplica o princípio do aberto e fechado (OCP)
  • Permite que você altere a cadeia de objetos e a ordem das chamadas facilmente

Ruim:

  • é comum uma requisição passar por toda a cadeia e não ser tratada
