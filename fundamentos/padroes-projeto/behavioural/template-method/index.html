Template Method - Behavioural (Comportamental)

Intenção

Define o esqueleto de um algoritmo em uma operação, postergando a definição de alguns passos para subclasses. O template method permite que as subclasses redefinam certos passos de um algoritmo sem mudar sua estrutura

Sobre o Template Method

Em vídeo: https://www.youtube.com/watch?v=-nSOKE4f2gA&list=PLbIBj8vQhvm0VY5YrMrafWaQY2EnJ3j8H&index=39

O Template Method é um padrão de projeto comportamental que define o esqueleto de um algoritmo em uma classe base, permitindo que subclasses personalizem partes específicas do comportamento sem modificar sua estrutura geral.

O Template Method é amplamente usado para processos padronizados com variações, como processamento de arquivos, relatórios, algoritmos de IA e engines de jogos.

Estrutura

Aplicabilidade

Use o Template Method quando:

  • você precisa de variações de um mesmo algoritmo sem mudar a ordem de execução dos métodos
  • você percebe que está usando herança para alterar apenas pequenos trechos de código de um algoritmo
  • Quando temos várias classes que compartilham uma estrutura comum, mas diferem em detalhes específicos.
  • Quando queremos evitar duplicação de código e promover o reuso.
  • Quando desejamos que subclasses sigam um fluxo predefinido, mas possam sobrescrever partes dele.

Implementação

Aqui está um exemplo do padrão Template Method em C#.

Exemplo: Processo de Fabricação de Bebidas

Vamos modelar um sistema de fabricação de bebidas (exemplo: chá e café).
A preparação de qualquer bebida quente segue um fluxo parecido:

  1. Ferver água.
  2. Adicionar o ingrediente principal (café ou chá).
  3. Adicionar condimentos opcionais (açúcar, leite, limão, etc.).
  4. Servir.

Usaremos o padrão Template Method para definir esse processo de forma genérica e permitir que cada bebida personalize apenas as etapas necessárias.

using System;

// Classe base com o Template Method
public abstract class Beverage
{
    // Template Method - Define o fluxo principal da receita
    public void PrepareRecipe()
    {
        BoilWater();
        Brew();
        PourInCup();
        if (CustomerWantsCondiments()) // Hook method
        {
            AddCondiments();
        }
    }

    // Métodos comuns para todas as bebidas
    private void BoilWater()
    {
        Console.WriteLine("Fervendo água...");
    }

    private void PourInCup()
    {
        Console.WriteLine("Servindo na xícara...");
    }

    // Métodos abstratos - devem ser implementados pelas subclasses
    protected abstract void Brew();
    protected abstract void AddCondiments();

    // Hook Method - Pode ser sobrescrito para personalizar comportamento
    protected virtual bool CustomerWantsCondiments()
    {
        return true; // Por padrão, adiciona condimentos
    }
}

// Subclasse concreta para preparar café
public class Coffee : Beverage
{
    protected override void Brew()
    {
        Console.WriteLine("Passando o café...");
    }

    protected override void AddCondiments()
    {
        Console.WriteLine("Adicionando açúcar e leite...");
    }
}

// Subclasse concreta para preparar chá
public class Tea : Beverage
{
    protected override void Brew()
    {
        Console.WriteLine("Infundindo o chá...");
    }

    protected override void AddCondiments()
    {
        Console.WriteLine("Adicionando limão...");
    }

    // Sobrescreve o hook method para evitar condimentos
    protected override bool CustomerWantsCondiments()
    {
        return false; // Chá sem condimentos
    }
}

// Programa principal
class Program
{
    static void Main()
    {
        Console.WriteLine("Preparando Café:");
        Beverage coffee = new Coffee();
        coffee.PrepareRecipe();

        Console.WriteLine("\nPreparando Chá:");
        Beverage tea = new Tea();
        tea.PrepareRecipe();
    }
}

Explicação

  1. Criamos a classe base Beverage com o método PrepareRecipe() que define a sequência das etapas.
  2. Os métodos BoilWater() e PourInCup() são genéricos, então ficam na classe base.
  3. Os métodos Brew() e AddCondiments() são abstratos, pois variam entre chá e café.
  4. Criamos um Hook Method CustomerWantsCondiments(), que pode ser sobrescrito para modificar o comportamento.
  5. Criamos as classes Coffee e Tea, que personalizam a preparação das bebidas.

Saída esperada

Preparando Café:
Fervendo água...
Passando o café...
Servindo na xícara...
Adicionando açúcar e leite...

Preparando Chá:
Fervendo água...
Infundindo o chá...
Servindo na xícara...

Perceba que o chá não adicionou condimentos, pois sobrescrevemos o método CustomerWantsCondiments() para retornar false. Isso demonstra a flexibilidade do padrão.

Consequências

O que é bom ou ruim no Template Method:

Bom:

  • Evita duplicação de código - Permite que múltiplas subclasses compartilhem a mesma lógica geral
  • Permite fácil alteração de algoritmos = Alterações no fluxo do processo podem ser feitas na classe base, afetando todas as subclasses.
  • Aplica o OCP e SRP - Subclasses podem modificar apenas partes específicas do algoritmo

Ruim:

  • Em alguns casos pode violar o LSP ao alterar o comportamento de métodos nas subclasses
