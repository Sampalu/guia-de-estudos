Escalabilidade (Vertical / Horizontal)

Escalabilidade se refere à capacidade de um sistema aumentar ou reduzir seus recursos para atender à demanda. Ela pode ser feita de duas formas principais: Vertical / Horizontal
Categories:
  • Cloud

  2 minute read  

Escalabilidade Vertical (Scale Up/Down)

A escalabilidade vertical significa aumentar ou diminuir a capacidade de um único recurso, como uma máquina virtual (EC2), banco de dados (RDS), etc.

✅ Como funciona?

  • Aumentar CPU, memória ou disco de um único servidor.
  • Substituir uma instância pequena por uma maior.
  • Indicado para cargas que exigem mais poder de processamento em um único nó.

⚠ Limitações

  • Existe um limite físico (máximo de CPU/RAM disponíveis).
  • Pode causar tempo de inatividade durante a troca do recurso.
  • Não melhora a disponibilidade, pois o sistema continua dependendo de um único nó.

👉 Exemplo na AWS:

  • Mudar uma instância EC2 t3.micro para uma t3.large.
  • Aumentar o armazenamento de um banco RDS de 50GB para 500GB.

Escalabilidade Horizontal (Scale Out/In)

A escalabilidade horizontal significa adicionar ou remover múltiplas instâncias para dividir a carga de trabalho.

✅ Como funciona?

  • Adicionar mais servidores ou containers para lidar com o tráfego crescente.
  • Melhor para sistemas distribuídos, garantindo mais disponibilidade e desempenho.
  • Funciona bem com balanceadores de carga (Elastic Load Balancer - ELB).

⚠ Limitações

  • Requer que a aplicação suporte múltiplos nós (arquitetura distribuída).
  • Pode exigir mudanças na persistência de dados para evitar problemas de concorrência.

👉 Exemplo na AWS:

  • Usar Auto Scaling Groups (ASG) para adicionar mais instâncias EC2 automaticamente quando a demanda cresce.
  • Usar Amazon ECS ou Kubernetes (EKS) para escalar containers horizontalmente.
  • Configurar um Load Balancer para distribuir requisições entre várias instâncias.

Qual usar?

  • Escalabilidade Vertical → Boa para cargas monolíticas ou aplicações legadas que não podem ser distribuídas.
  • Escalabilidade Horizontal → Melhor para aplicações modernas e distribuídas, garantindo alta disponibilidade e desempenho.

O ideal é combinar ambas: usar escalabilidade horizontal para lidar com crescimento e disponibilidade, mas, quando necessário, também escalar verticalmente recursos individuais para otimizar desempenho.
