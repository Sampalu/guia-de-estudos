Estratégias de Deploy: Blue-Green e Canary

Quando se trata de deploy de aplicações, especialmente em ambientes de produção, a forma como novas versões são introduzidas pode impactar diretamente a disponibilidade, desempenho e experiência do usuário. Para minimizar riscos e garantir um lançamento suave, existem estratégias como Blue-Green Deployment e Canary Deployment.

1️⃣ Blue-Green Deployment

O Blue-Green Deployment é uma estratégia que envolve manter duas versões do ambiente:

  • Blue (Atual/Produção) → Representa a versão ativa e em funcionamento do sistema.
  • Green (Nova versão) → Uma nova versão da aplicação que será testada antes de substituir a Blue.

Como funciona?

  1. A nova versão (Green) é implantada e testada em paralelo à versão atual (Blue).
  2. Quando a Green estiver estável, o tráfego de usuários é redirecionado da Blue para a Green.
  3. Caso ocorra algum problema, o tráfego pode ser rapidamente revertido para a Blue (rollback imediato).

Vantagens do Blue-Green

✅ Downtime mínimo – A troca entre versões é instantânea.
✅ Rollback rápido – Se houver falha, é fácil voltar para a versão anterior.
✅ Testes em produção – A nova versão pode ser validada antes do tráfego real.

Desvantagens

❌ Custo alto – Duas infraestruturas precisam ser mantidas simultaneamente.
❌ Dados podem ser um problema – Se houver mudanças no banco de dados, reverter para a Blue pode ser complicado.

Quando usar?

  • Aplicações críticas que exigem alta disponibilidade.
  • Sistemas onde rollback rápido é essencial.
  • Ambientes onde o custo extra é justificável.

2️⃣ Canary Deployment

O Canary Deployment é uma estratégia de lançamento gradual, onde a nova versão é implantada para um pequeno grupo de usuários antes de ser liberada para todos.

Como funciona?

  1. A nova versão da aplicação é implantada em uma pequena porcentagem dos servidores.
  2. Apenas uma pequena parcela dos usuários recebe a nova versão (exemplo: 5% do tráfego).
  3. Monitoramento contínuo é feito para detectar erros, desempenho e feedback.
  4. Se tudo estiver estável, a nova versão é progressivamente expandida até atingir 100% dos usuários.
  5. Se um problema for identificado, o tráfego pode ser revertido para a versão anterior.

Vantagens do Canary Deployment

✅ Menos impacto em caso de falha – Apenas um grupo pequeno de usuários pode ser afetado inicialmente.
✅ Ajustes progressivos – Permite corrigir erros antes de um lançamento completo.
✅ Experimentos controlados – Facilita testes A/B e otimizações de desempenho.

Desvantagens

❌ Mais complexidade – Requer roteamento de tráfego inteligente e monitoramento detalhado.
❌ Rollback pode levar mais tempo – Se houver um problema em uma fase avançada, pode ser necessário uma reversão mais complicada.

Quando usar?

  • Aplicações de larga escala (exemplo: Facebook, Google, AWS).
  • Sistemas com grande base de usuários onde um erro pode causar grandes impactos.
  • Quando testes em produção precisam ser feitos sem afetar todos os usuários.

Comparação: Blue-Green vs. Canary

CritérioBlue-Green DeploymentCanary Deployment
DesempenhoMuito rápido, com troca instantâneaGradual, depende da análise contínua
RollbackInstantâneo, só precisa reverter o tráfegoPode ser demorado, dependendo do progresso do rollout
RiscoBaixo, pois há um ambiente pronto para fallbackMais seguro, pois os problemas são detectados antes da liberação total
ComplexidadeSimples de implementar, mas exige infraestrutura duplicadaComplexo, exige roteamento de tráfego inteligente
CustoAlto (mantém dois ambientes simultaneamente)Mais econômico, pois usa os mesmos servidores
Uso recomendadoAplicações críticas com necessidade de rollback rápidoAplicações com muitos usuários e que podem ser liberadas gradualmente

Qual escolher?

🔹 Se a prioridade é rollback instantâneo, o Blue-Green Deployment é a melhor escolha.
🔹 Se o objetivo é testar gradualmente sem impactar todos os usuários, o Canary Deployment é a melhor abordagem.
🔹 Muitas empresas combinam ambas as estratégias: usam Blue-Green para grandes lançamentos e Canary para mudanças menores.

Estratégias de Deploy na AWS

A AWS oferece diversas ferramentas para facilitar esses tipos de deploy:

  • AWS Elastic Beanstalk → Suporta Blue-Green automaticamente.
  • AWS CodeDeploy → Suporta Blue-Green e Canary para EC2, Lambda e ECS.
  • Amazon ECS e EKS → Usam roteamento e balanceamento de carga para Canary Deployment.
  • AWS Lambda → Suporta Canary Deployment nativamente com roteamento de tráfego gradual.

Essas estratégias garantem deploys seguros, escaláveis e eficientes!
