1. Introdução à Autenticação

O que é autenticação?

Autenticação é o processo de verificar a identidade de um usuário ou sistema. Isso pode ser feito por meio de credenciais, como:

  • Usuário e senha
  • Biometria (impressão digital, reconhecimento facial)
  • Certificados digitais
  • Tokens de autenticação

Diferença entre Autenticação e Autorização

  • Autenticação: Verifica quem está acessando o sistema.
  • Autorização: Define o que esse usuário pode acessar dentro do sistema.

Exemplo:

  • Quando você faz login no Google, o sistema verifica sua identidade (autenticação).
  • Depois que você está logado, o sistema decide quais serviços você pode acessar (autorização).

2. Basic Authentication

Como funciona?

  • O usuário fornece um nome de usuário e senha.
  • Essas credenciais são enviadas no cabeçalho HTTP de cada requisição, codificadas em Base64:
    Authorization: Basic dXNlcm5hbWU6cGFzc3dvcmQ=
  • O servidor decodifica e verifica as credenciais.

Limitações

  • Inseguro: As credenciais são enviadas a cada requisição e podem ser interceptadas.
  • Não escalável: Não há suporte para logout sem fechar a sessão do navegador.
  • Melhoria: Deve ser usada apenas em conjunto com HTTPS para proteção.

3. Session-Based Authentication

Como funciona?

  1. O usuário faz login e o servidor cria uma sessão.
  2. Um identificador de sessão é armazenado em um cookie no navegador.
  3. Em cada requisição, o navegador envia esse cookie, permitindo que o servidor reconheça o usuário.

Problemas

  • Escalabilidade: O estado da sessão é mantido no servidor, o que pode sobrecarregar a memória em aplicações grandes.
  • Gerenciamento de sessões: Sessões expiram e precisam ser armazenadas de forma segura.
  • Requer configuração correta de cookies: Caso contrário, pode haver ataques como Session Hijacking.

4. Token-Based Authentication

Como funciona?

  • Em vez de sessões, o servidor gera um token e o envia ao cliente.
  • O cliente armazena esse token e o inclui em cada requisição HTTP (por exemplo, no cabeçalho Authorization: Bearer <token>).
  • O servidor verifica o token em cada requisição.

Benefícios

  • Escalabilidade: O servidor não precisa armazenar sessões.
  • Funciona bem para APIs: Como o token pode ser usado em qualquer requisição HTTP.
  • Permite clientes distribuídos: Web, mobile e outros dispositivos podem usar o mesmo token.

5. JWT Authentication (JSON Web Token)

O que é JWT?

O JSON Web Token (JWT) é um formato de token usado em autenticação. Ele tem três partes:

  1. Header: Contém informações sobre o algoritmo de assinatura.
  2. Payload: Contém informações sobre o usuário e permissões.
  3. Signature: Garante que o token não foi modificado.

Um JWT tem a seguinte estrutura:

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.
eyJ1c2VySWQiOiIxMjM0NSIsInJvbGUiOiJhZG1pbiJ9.
SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c

Vantagens e Desvantagens

✅ Vantagens
✔ Autossuficiente (não requer estado no servidor).
✔ Pode ser usado para SSO (Single Sign-On).
✔ Melhor desempenho que sessões baseadas no servidor.

🚫 Desvantagens
❌ Não pode ser revogado facilmente sem um banco de dados adicional.
❌ Pode crescer muito se armazenar muitos dados no payload.

6. OAuth (Open Authorization)

O que é OAuth?

OAuth 2.0 é um protocolo que permite que aplicativos acessem recursos protegidos sem compartilhar credenciais do usuário.

Fluxos principais do OAuth

  • Authorization Code Flow (para aplicativos web seguros).
  • Client Credentials Flow (para comunicação entre servidores).
  • Resource Owner Password Credentials Flow (obsoleto).
  • Implicit Flow (obsoleto).

Exemplo de uso

Quando um aplicativo solicita permissão para acessar sua conta do Google, ele usa OAuth.

7. OpenID

O que é OpenID?

OpenID Connect é uma camada de autenticação sobre OAuth 2.0. Ele permite que os usuários façam login em diferentes serviços com uma única conta.

Diferença entre OpenID e OAuth

  • OAuth: Trata da autorização (quem pode acessar seus dados).
  • OpenID Connect: Trata da autenticação (verificação da identidade do usuário).

Exemplo:

  • OAuth: Um app pede acesso aos seus contatos no Google.
  • OpenID Connect: Um app permite que você faça login com sua conta do Google.

8. SSO (Single Sign-On)

O que é SSO?

Single Sign-On (SSO) permite que os usuários acessem vários sistemas usando um único login.

Como funciona?

  • O usuário faz login uma vez em um provedor de identidade (IdP).
  • Outros serviços confiam nesse login e não exigem novas credenciais.

Tecnologias comuns de SSO

  • OAuth/OpenID Connect (para web e mobile).
  • SAML (para empresas).
  • Kerberos (para redes corporativas).

Exemplo:

  • Com o login da Microsoft, você pode acessar Outlook, OneDrive e Teams sem precisar autenticar novamente.

9. SAML (Security Assertion Markup Language)

O que é SAML?

SAML é um protocolo usado para SSO corporativo. Ele permite que um usuário se autentique uma vez e acesse vários sistemas empresariais.

Fluxo de autenticação SAML

  1. O usuário tenta acessar um sistema (Service Provider - SP).
  2. O SP redireciona para um Identity Provider (IdP).
  3. O usuário autentica no IdP.
  4. O IdP retorna um SAML Assertion, que o SP usa para autenticar o usuário.

Diferença entre SAML e OAuth/OpenID

  • SAML: Usado para autenticação corporativa (empresas).
  • OAuth/OpenID: Usado para autenticação na web e mobile.

10. STS (Security Token Service)

O que é um STS?

STS é um serviço que emite tokens de segurança para autenticação e autorização.

Como funciona?

  1. Um usuário ou sistema solicita um token ao STS.
  2. O STS verifica as credenciais e gera um token.
  3. O token é usado para acessar serviços protegidos.

Exemplo de STS

  • O AWS Security Token Service (AWS STS) emite tokens temporários para acessar recursos na AWS.
  • O Microsoft Entra ID pode atuar como STS para emissão de tokens JWT.
