Authorization Server

O Authorization Server (Servidor de Autorização) é um componente central em protocolos de autenticação e autorização, como o OAuth 2.0 e o OpenID Connect. Ele é responsável por autenticar usuários e conceder tokens de acesso a aplicativos clientes, permitindo que esses aplicativos acessem recursos protegidos sem precisar armazenar ou manipular diretamente as credenciais do usuário.

Principais funções de um Authorization Server

  1. Autenticação do Usuário

    • Verifica se as credenciais do usuário são válidas (por exemplo, login e senha, autenticação multifator, etc.).

  2. Emissão de Tokens

    • Após autenticar o usuário, o Authorization Server gera e retorna um token de acesso (Access Token), que pode ser usado para acessar APIs protegidas.
    • Pode também emitir um token de atualização (Refresh Token), que permite obter novos tokens de acesso sem precisar autenticar novamente o usuário.

  3. Gerenciamento de Permissões (Scopes)

    • Controla quais permissões o usuário concede ao aplicativo cliente (por exemplo, acesso ao e-mail, lista de contatos, etc.).

  4. Validação e Expiração de Tokens

    • Define regras de validade dos tokens e pode revogá-los se necessário.

Exemplos de Authorization Servers Populares

  • Auth0
  • AWS Cognito
  • Google Identity Platform
  • Microsoft Entra ID (antigo Azure AD)
  • Keycloak (Open Source)

Diferença entre Authorization Server e Authentication Server

  • Authentication Server: Confirma a identidade do usuário (quem ele é).
  • Authorization Server: Concede permissões e tokens para que um aplicativo possa acessar recursos protegidos.

Em resumo, o Authorization Server é a peça-chave que intermedia a autenticação e a concessão de acesso seguro em sistemas baseados em OAuth 2.0 e OpenID Connect.
