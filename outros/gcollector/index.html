Garbage Collector (GC)

Categories:
  • Outros

  5 minute read  

O Garbage Collector (GC) do .NET continua a evoluir para melhorar a eficiência da coleta de lixo e otimizar a performance das aplicações. Ele mantém os princípios fundamentais das versões anteriores, mas com aprimoramentos para melhor uso da memória e menor impacto na execução da aplicação.

1. Como Funciona o Garbage Collector no .NET?

O GC no .NET trabalha em um modelo geracional, onde os objetos alocados são categorizados em três gerações:

  • Geração 0: Objetos de curta duração, como variáveis locais.
  • Geração 1: Objetos que sobreviveram a uma coleta na Geração 0.
  • Geração 2: Objetos de longa duração, como caches e singletons.

O coletor de lixo tenta liberar memória primeiro na Geração 0 e só passa para as gerações superiores se necessário. Isso melhora a eficiência porque objetos curtos são rapidamente removidos e os objetos de longa duração não são verificados com tanta frequência.

2. Novidades e Melhorias no .NET 8

O .NET 8 trouxe algumas otimizações importantes no GC:

2.1. Melhorias de Performance e Eficiência

  • Menor tempo de pausa: O GC no .NET 8 foi aprimorado para reduzir os tempos de pausa ao gerenciar a memória, especialmente em aplicações de alto desempenho.
  • Melhoria no “Pinned Object Heap” (POH): Objetos fixados (“pinned”) agora têm melhor gerenciamento, evitando fragmentação da memória.
  • Otimizações para servidores com grande capacidade de memória: O GC se adapta melhor a máquinas com muita RAM, otimizando alocações e coletas.

2.2. Ajustes Dinâmicos de Threads do GC

  • O GC agora ajusta dinamicamente o número de threads usadas para coleta, dependendo da carga do sistema. Isso melhora a escalabilidade em sistemas multi-thread.

2.3. Melhorias no “LOH Compaction”

  • O Large Object Heap (LOH), onde objetos grandes são armazenados, agora tem melhores estratégias para compactação, reduzindo fragmentação da memória.

3. Modos de Execução do GC

O .NET 8 mantém os dois principais modos do GC:

  • GC Workstation: Otimizado para aplicações desktop e single-threaded.
  • GC Server: Otimizado para aplicações de servidor, onde múltiplas threads gerenciam a coleta de lixo simultaneamente.

Agora, com os ajustes dinâmicos, o modo Server GC tem uma adaptação ainda melhor para cargas variáveis.

4. Como Configurar e Monitorar o GC?

Você pode ajustar o comportamento do GC via configuração no runtimeconfig.json ou usando variáveis de ambiente:

Configuração via JSON

{
  "runtimeOptions": {
    "configProperties": {
      "System.GC.Server": true,
      "System.GC.Concurrent": true
    }
  }
}

Configuração via Código

GCSettings.LatencyMode = GCLatencyMode.LowLatency;

Monitoramento com EventCounters

No .NET 8, você pode monitorar a atividade do GC usando dotnet-counters:

dotnet-counters monitor --process-id <PID>

Conclusão

O GC do .NET 8 mantém o modelo generacional eficiente, mas com várias otimizações para reduzir pausas, melhorar o gerenciamento de objetos grandes e aumentar a escalabilidade. Isso torna o .NET 8 uma opção ainda mais robusta para aplicações de alta performance.

Aqui está um exemplo prático que demonstra o funcionamento do Garbage Collector (GC) no .NET 8, incluindo a alocação de memória, a coleta de lixo e a observação do comportamento das gerações.

Código de Exemplo

Este código cria objetos em diferentes gerações e força a coleta de lixo para ilustrar o processo:

using System;
using System.Threading;
using System.Runtime;

class Program
{
    static void Main()
    {
        Console.WriteLine($"Modo do GC: {GCSettings.IsServerGC}");
        
        // Criamos muitos objetos para alocação na Geração 0
        for (int i = 0; i < 100_000; i++)
        {
            _ = new object();
        }

        // Criamos um objeto que vai sobreviver à coleta e passar para Geração 1
        object obj1 = new object();

        // Criamos um objeto maior que vai para o Large Object Heap (LOH)
        byte[] largeObject = new byte[85_000]; // > 85 KB = LOH

        Console.WriteLine($"Geração do obj1 antes da coleta: {GC.GetGeneration(obj1)}");
        Console.WriteLine($"Geração do largeObject antes da coleta: {GC.GetGeneration(largeObject)}");

        // Forçamos a coleta de lixo em todas as gerações
        GC.Collect();
        GC.WaitForPendingFinalizers();

        Console.WriteLine($"Geração do obj1 após a coleta: {GC.GetGeneration(obj1)}");
        Console.WriteLine($"Geração do largeObject após a coleta: {GC.GetGeneration(largeObject)}");

        // Exibir memória usada
        Console.WriteLine($"Memória usada: {GC.GetTotalMemory(false) / 1024} KB");
    }
}

Explicação do Código

  1. Exibe se o GC está rodando no modo Server (útil para aplicações de servidor).
  2. Cria 100.000 objetos que inicialmente ficam na Geração 0.
  3. Cria um objeto persistente (obj1) que sobreviverá e poderá ser promovido para a Geração 1.
  4. Cria um grande array (largeObject) com mais de 85 KB, que é alocado diretamente no Large Object Heap (LOH).
  5. Exibe a geração de cada objeto antes da coleta.
  6. Força a coleta de lixo com GC.Collect() e GC.WaitForPendingFinalizers().
  7. Exibe novamente a geração de cada objeto para mostrar se houve promoção para uma geração superior.
  8. Exibe o uso total de memória após a coleta.

Saída Esperada (Aproximada)

Modo do GC: True
Geração do obj1 antes da coleta: 0
Geração do largeObject antes da coleta: 2
Geração do obj1 após a coleta: 1
Geração do largeObject após a coleta: 2
Memória usada: 15000 KB

O que Acontece Aqui?

  • obj1 começa na Geração 0, mas sobrevive à coleta e é promovido para a Geração 1.
  • largeObject já está na Geração 2, pois objetos no LOH nunca são promovidos entre gerações.
  • GC.Collect() limpa a Geração 0, mas mantém objetos ainda referenciados.

Conclusão

Esse exemplo mostra como o GC no .NET 8 gerencia alocações e coletas, promovendo objetos entre gerações para otimizar o desempenho e reduzir pausas na aplicação.
