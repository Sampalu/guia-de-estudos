Apache Kafka

Apache Kafka é uma plataforma distribuída de streaming de eventos usada para coletar, processar, armazenar e distribuir fluxos de dados em tempo real. Ele é altamente escalável e foi projetado para lidar com grandes volumes de dados de forma confiável e eficiente.

  • Filas De Mensagens

  5 minute read  

1. Conceito

Kafka é um sistema de mensageria distribuída que utiliza um modelo publish-subscribe para transmissão de eventos. Ele permite que produtores enviem mensagens para tópicos e consumidores leiam essas mensagens.

Principais casos de uso:

  • Processamento de eventos em tempo real
  • Integração entre microsserviços
  • Monitoramento e análise de logs
  • Streaming de dados para análise em Big Data

2. Arquitetura do Apache Kafka

A arquitetura do Kafka é composta pelos seguintes componentes:

  • Producer (Produtor): Envia mensagens para um tópico no Kafka.
  • Broker: Servidor do Kafka que recebe, armazena e distribui mensagens.
  • Topic (Tópico): Canal lógico onde as mensagens são publicadas.
  • Partition (Partição): Divide um tópico em múltiplas partes para escalabilidade.
  • Consumer (Consumidor): Lê mensagens de um tópico.
  • Consumer Group (Grupo de Consumidores): Conjunto de consumidores que compartilham a leitura de um tópico.
  • Zookeeper: Coordena os brokers e gerencia metadados do Kafka.

3. Produtores e Consumidores

Os produtores enviam mensagens para tópicos específicos. Eles podem escolher para qual partição enviar as mensagens, seja de forma manual ou automática (por um hash da chave da mensagem).

Os consumidores leem mensagens de um tópico e podem pertencer a um Consumer Group. Se vários consumidores fazem parte do mesmo grupo, cada mensagem será processada por apenas um consumidor desse grupo.

4. Utilização das Partições

Cada tópico pode ser dividido em partições, o que permite:

  • Escalar horizontalmente a carga entre vários consumidores
  • Garantir um nível de paralelismo na leitura das mensagens

Exemplo prático

Imagine um tópico chamado “Pedidos” com 3 partições. Se tivermos um grupo de consumidores com 3 instâncias, cada consumidor lerá as mensagens de uma partição diferente.

Pedido IDPartição
10010
10021
10032
10040

Se tivermos um único consumidor, ele lerá todas as partições, mas com múltiplos consumidores no grupo, cada um pegará uma parte dos dados.

5. Como manter a ordem das mensagens?

Por padrão, Kafka não garante a ordem das mensagens entre partições diferentes, mas garante dentro de uma mesma partição.

Como evitar desordem?

  • Usar a mesma chave de particionamento para mensagens que precisam estar ordenadas. Kafka usa um hash da chave para definir a partição.
  • Manter apenas um consumidor por partição no grupo.
  • Configurar a política de retries corretamente, pois tentativas de reenvio podem alterar a ordem.

Exemplo prático:

Sem chave (Round-Robin)

for i in range(10):
    producer.send('meu_topico', value=f'Mensagem {i}'.encode())
  • O Kafka distribui as mensagens de forma balanceada (round-robin) entre as partições.

Com chave (Determinístico)

producer.send('meu_topico', key=b'cliente123', value=b'Compra feita!')
  • Sempre que a chave ‘cliente123’ for usada, a mensagem vai para a mesma partição (garantindo ordenação).

6. Quando usar um Grupo de Consumidores?

Quando você quer processar as mensagens de um tópico de forma escalável, sem que cada instância processe as mesmas mensagens. Ou seja, cada mensagem será processada apenas uma vez dentro do grupo.

Exemplo prático: Processamento paralelo de pedidos

Imagine que você tem um tópico “pedidos” com 10 partições e um sistema de processamento de pedidos.

  • Se você tiver 1 único consumidor → Ele precisa ler e processar mensagens de todas as 10 partições sozinho.
  • Se você criar um Consumer Group com 5 consumidores → O Kafka divide as partições entre eles (2 partições por consumidor), permitindo um processamento 5x mais rápido.

7. Como o Kafka distribui as partições?

  1. Se houver menos consumidores que partições, cada consumidor recebe uma ou mais partições.

    • Exemplo: 10 partições, 5 consumidores → Cada consumidor recebe 2 partições.

  2. Se houver mais consumidores que partições, alguns consumidores ficarão ociosos.

    • Exemplo: 10 partições, 15 consumidores → Apenas 10 consumidores terão partições, e os outros 5 ficarão sem dados.

8. Confirmação de Mensagens (ACKs)

O Kafka permite configurar como os produtores confirmam que uma mensagem foi recebida pelo broker.

Tipos de ACKs

  1. ACK=0 (Sem confirmação)

    • O produtor não espera resposta do broker.
    • Rápido, mas pode perder mensagens se o broker falhar.

  2. ACK=1 (Confirmação do líder da partição)

    • O produtor recebe a confirmação assim que o líder da partição armazena a mensagem.
    • Se o líder falhar antes da replicação, pode haver perda de dados.

  3. ACK=all (Confirmação de todos os brokers réplicas)

    • A mensagem só é considerada confirmada quando todas as réplicas sincronizadas salvam a mensagem.
    • Mais seguro, mas pode impactar a latência.

Exemplo de configuração:

producer = KafkaProducer(
    bootstrap_servers='localhost:9092',
    acks='all'
)

9. Controle de Confirmação no Consumidor

O consumidor pode confirmar a leitura das mensagens de duas formas:

9.1 Autocommit (Confirmação automática)

O Kafka pode confirmar automaticamente a leitura das mensagens.

KafkaConsumer('meu_topico', enable_auto_commit=True)
  • Prós: Fácil de usar.
  • Contras: Pode perder mensagens se o consumidor falhar antes do processamento.

9.2 Commit manual (Controle pelo sistema)

O consumidor pode processar a mensagem e só depois confirmar a leitura.

consumer = KafkaConsumer('meu_topico', enable_auto_commit=False)

for message in consumer:
    print(f"Processando {message.value}")
    consumer.commit()
  • Prós: Evita perda de mensagens não processadas.
  • Contras: Requer mais controle no código.

Resumo

CenárioO que acontece?
Sem grupo de consumidores (diferentes sistemas)Todos os consumidores recebem todas as mensagens.
Com grupo de consumidores (mesmo sistema, múltiplas instâncias)O Kafka divide as mensagens entre os consumidores do grupo.
Mais consumidores do que partiçõesAlguns consumidores ficam ociosos.
Menos consumidores do que partiçõesAlguns consumidores processam mais mensagens do que outros.

Conclusão

Apache Kafka é uma ferramenta poderosa para processamento e transmissão de dados em tempo real. Ele fornece escalabilidade através das partições, mantém a confiabilidade com diferentes níveis de ACKs, e permite controle sobre a entrega e processamento das mensagens através de Consumer Groups e commits manuais.
