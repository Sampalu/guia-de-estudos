Protocolos e Padrões de Comunicação

(HTTP, REST, GraphQL, WebSockets, gRPC e RPC)
Tags:
  • Protocolos
Categories:
  • Modelos Arquiteturais

  3 minute read  

Aqui está um resumo dos principais protocolos e padrões de comunicação usados em aplicações web e distribuídas:

1. HTTP (HyperText Transfer Protocol)

O HTTP é o protocolo base da web, usado para comunicação entre clientes (como navegadores) e servidores. Ele funciona no modelo request-response, onde o cliente faz uma requisição e o servidor responde.

  • Usa métodos como GET, POST, PUT, DELETE para manipular recursos.
  • Funciona sobre TCP, geralmente na porta 80 (HTTP) ou 443 (HTTPS).
  • É stateless: cada requisição é independente.

2. REST (Representational State Transfer)

REST é um estilo arquitetural para construir APIs baseadas em HTTP. Ele segue princípios como:

  • Recursos identificáveis por URLs (ex: /users/1 representa o usuário de ID 1).
  • Uso de métodos HTTP apropriados (GET para ler, POST para criar, etc.).
  • Stateless: o servidor não mantém estado entre requisições.
  • Representação do recurso pode ser JSON, XML, etc.

🔹 Diferença entre REST e RESTful:

  • REST: Apenas o conceito arquitetural.
  • RESTful: Aplicação que segue todos os princípios do REST corretamente.

3. GraphQL

GraphQL é uma alternativa ao REST, criada pelo Facebook, que permite consultas mais flexíveis.

  • O cliente especifica os dados que quer, evitando over-fetching (dados desnecessários) e under-fetching (dados insuficientes).
  • Usa apenas um endpoint (/graphql).
  • Baseado em tipos e esquema.
  • Pode ser mais eficiente do que REST em algumas situações.

Exemplo de query GraphQL:

query {
  user(id: 1) {
    name
    email
  }
}

Resposta:

{
  "data": {
    "user": {
      "name": "João",
      "email": "joao@email.com"
    }
  }
}

4. WebSockets

Diferente de HTTP, o WebSocket permite comunicação bidirecional e em tempo real entre cliente e servidor.

  • Ideal para chats, jogos, notificações.
  • Mantém uma conexão aberta, ao invés de múltiplas requisições como no HTTP.
  • Funciona sobre TCP, utilizando o handshake inicial via HTTP.

Exemplo de WebSocket:

const socket = new WebSocket("wss://meuservidor.com/socket");

socket.onmessage = (event) => {
  console.log("Mensagem recebida:", event.data);
};

5. gRPC (Google Remote Procedure Call)

gRPC é um framework de comunicação de alta performance baseado em RPC (Remote Procedure Call) e usa Protocol Buffers (protobuf) para serialização.

  • Mais rápido e eficiente que REST e GraphQL.
  • Comunicação binária, economizando banda.
  • Suporte a múltiplos idiomas (Java, C#, Go, Python, etc.).
  • Streaming bidirecional (server e client podem enviar dados simultaneamente).

Exemplo de definição Protobuf para gRPC:

service UserService {
  rpc GetUser (UserRequest) returns (UserResponse);
}

6. RPC (Remote Procedure Call)

RPC é um modelo de comunicação onde um sistema pode chamar funções remotas como se fossem funções locais.

  • Pode ser síncrono ou assíncrono.
  • Implementações famosas: gRPC, JSON-RPC, XML-RPC.
  • Mais acoplado que REST, mas pode ser mais eficiente.

Exemplo de JSON-RPC:

{
  "jsonrpc": "2.0",
  "method": "getUser",
  "params": {"id": 1},
  "id": 1
}
