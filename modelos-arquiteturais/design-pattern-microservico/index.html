Arquitetura Monolítica

A arquitetura monolítica é um modelo tradicional de desenvolvimento de software onde toda a aplicação é construída como uma única unidade indivisível. Isso significa que todos os componentes – como interface de usuário, lógica de negócios e acesso a dados – estão altamente integrados dentro do mesmo código-base e executados como um único processo.

Microserviços

Microserviços são um estilo de arquitetura de software em que uma aplicação é dividida em pequenos serviços independentes que se comunicam entre si, geralmente por meio de APIs (REST, gRPC ou Mensageria). Cada microserviço é responsável por uma função específica do sistema e pode ser desenvolvido, implantado e escalado separadamente.

API Gateway

O padrão de design de Microserviços com API Gateway é uma abordagem amplamente adotada em arquiteturas de microserviços para lidar com a complexidade e fornecer um ponto de entrada centralizado para todas as interações com os serviços. O API Gateway atua como um intermediário entre os clientes e os microserviços, oferecendo diversos benefícios, como simplificação das interações e centralização do gerenciamento de tráfego.

DDD

Domain-Driven Design (DDD) é uma abordagem para o desenvolvimento de software que foca em entender e modelar o domínio do negócio de forma aprofundada, garantindo que o software reflita a realidade da organização. Foi introduzida por Eric Evans no livro Domain-Driven Design: Tackling Complexity in the Heart of Software.

CQRS (Command Query Responsibility Segregation)

CQRS (Segregação de Responsabilidade entre Comando e Consulta) é um padrão arquitetural que separa operações de leitura (Query) e escrita (Command) em um sistema. O objetivo principal é melhorar a escalabilidade, desempenho e segurança, evitando que consultas afetem a performance das operações de escrita e vice-versa.

EDA - Event-Driven Architecture (Arquitetura Orientada a Eventos)

EDA (Event-Driven Architecture) é um modelo arquitetural baseado em eventos para comunicação entre sistemas e componentes. Em vez de depender de chamadas diretas entre serviços, os componentes reagem a eventos de forma assíncrona, tornando o sistema mais desacoplado, escalável e resiliente.

Event Sourcing

Event Sourcing é um padrão arquitetural onde o estado de um sistema é derivado de uma sequência de eventos em vez de armazenar diretamente o estado atual em um banco de dados tradicional.
Ao invés de simplesmente armazenar a última versão dos dados, o Event Sourcing mantém um histórico completo de todas as mudanças feitas no sistema na forma de eventos imutáveis. Isso permite reconstruir o estado do sistema a qualquer momento, fornecendo rastreabilidade e auditabilidade total.

Event Storming

Event Storming é uma técnica colaborativa para explorar, modelar e entender sistemas complexos baseados em eventos. Foi criada por Alberto Brandolini e é amplamente usada no Domain-Driven Design (DDD) para mapear processos de negócio e identificar eventos importantes.
Diferente de métodos tradicionais de documentação, o Event Storming usa um workshop interativo onde participantes discutem e registram eventos importantes do domínio do sistema em post-its coloridos ou ferramentas digitais.

Saga

O padrão Saga é uma abordagem para gerenciar transações distribuídas em arquiteturas de microserviços. Como, em um ambiente distribuído, não há um gerenciador central de transações como nos bancos de dados relacionais (com ACID), o Saga divide a transação global em uma sequência de transações locais coordenadas de forma que, se algo falhar, o sistema possa ser restaurado a um estado consistente.
O Saga entra na categoria de Padrões de Comunicação Assíncrona, especificamente na coordenação de transações distribuídas. Ele é um padrão usado quando uma operação envolve múltiplos microserviços e precisa garantir consistência sem bloquear tudo com um banco de dados transacional centralizado.

Arquitetura Orientada a Eventos: Orquestrada

Na arquitetura orquestrada, um orquestrador central (geralmente um serviço dedicado, como um workflow engine) controla a execução dos eventos e a comunicação entre os serviços.

Arquitetura Orientada a Eventos: Coreografada

Na arquitetura coreografada, não há um serviço central controlando o fluxo. Em vez disso, os serviços publicam e escutam eventos, reagindo a eles de forma independente.

Camada Anticorrupção (Anticorruption Layer - ACL)

A Camada Anticorrupção (Anticorruption Layer - ACL) é um padrão arquitetural que atua como uma barreira entre dois sistemas ou contextos de software que possuem modelos diferentes. O objetivo é evitar que um sistema seja ‘corrompido’ pelos conceitos, terminologias ou regras de negócio de outro sistema, garantindo um isolamento adequado.

Backend for Frontend (BFF)

O Backend for Frontend (BFF) é um padrão arquitetural onde um backend específico é criado para atender às necessidades de um determinado frontend. Diferente de uma API genérica usada por múltiplos clientes, o BFF atua como uma camada intermediária otimizada para um tipo específico de aplicação (web, mobile, desktop, etc.).
