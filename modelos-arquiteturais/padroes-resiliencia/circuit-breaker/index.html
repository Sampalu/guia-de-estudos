Circuit Breaker (Disjuntor)

Impede que um serviço sobrecarregado continue processando solicitações e cause falhas em cascata. Se uma operação falha repetidamente, o circuito é aberto e as chamadas subsequentes são bloqueadas por um tempo antes de permitir novas tentativas.
Exemplo: Netflix usa este padrão no Hystrix para evitar sobrecarga em seus serviços.
Categories:
  • Cloud

  3 minute read  

O padrão Circuit Breaker (Disjuntor) é um mecanismo de resiliência usado para evitar falhas em cascata em sistemas distribuídos. Ele monitora falhas em chamadas para serviços externos e interrompe temporariamente as requisições quando detecta um número excessivo de erros.

A ideia é parecida com um disjuntor elétrico: se um serviço está falhando repetidamente, o circuito abre e impede novas chamadas até que o sistema se recupere. Isso evita sobrecarregar um serviço que já está instável.

Estados do Circuit Breaker

O Circuit Breaker pode estar em três estados:

  1. Fechado (Closed) – Operação Normal

    • As chamadas fluem normalmente para o serviço externo.
    • Se falhas ocorrem, o Circuit Breaker conta os erros.
    • Se o número de falhas atinge um limite configurado, o disjuntor “abre”.

  2. Aberto (Open) – Bloqueando Requisições

    • O sistema para de enviar requisições para o serviço externo.
    • Durante esse tempo, qualquer tentativa de chamada falha imediatamente.
    • Após um período de espera, o circuito muda para o estado meio aberto.

  3. Meio Aberto (Half-Open) – Testando a Recuperação

    • Permite algumas requisições de teste para verificar se o serviço voltou ao normal.
    • Se as requisições de teste forem bem-sucedidas, o circuito fecha novamente e o tráfego normal é retomado.
    • Se as falhas persistirem, o circuito volta a ficar aberto.

Exemplo Prático

Imagine um sistema de e-commerce que depende de um serviço externo de pagamento. Se o serviço de pagamento começar a falhar, um Circuit Breaker pode:
Fechar → Permitir chamadas enquanto o serviço está funcionando.
Abrir → Bloquear chamadas após um número excessivo de falhas, evitando sobrecarga.
Meio Abrir → Testar o serviço periodicamente para ver se está recuperado.

Sem o Circuit Breaker:

  • O sistema pode continuar enviando requisições para um serviço instável, causando timeouts e afetando a experiência do usuário.

Com o Circuit Breaker:

  • Ele corta as requisições rapidamente, permitindo que o sistema degrade de forma controlada e evite falhas em cascata.

Implementação do Circuit Breaker

Exemplo com Resilience4j (Java/Spring Boot)

@CircuitBreaker(name = "pagamentoService", fallbackMethod = "fallbackPagamento")
public String processarPagamento() {
    return restTemplate.getForObject("https://api.pagamento.com/processar", String.class);
}

public String fallbackPagamento(Exception e) {
    return "O serviço de pagamento está indisponível. Tente novamente mais tarde.";
}

🔹 Se o serviço de pagamento falhar repetidamente, o Circuit Breaker abre e retorna o fallback.

Vantagens do Circuit Breaker

✅ Evita falhas em cascata → Se um serviço falha, o resto do sistema continua funcionando.
✅ Melhora a experiência do usuário → Em vez de uma falha completa, o sistema pode fornecer uma resposta alternativa.
✅ Protege serviços contra sobrecarga → Se um serviço está sobrecarregado, evita que ele receba mais requisições até que se recupere.
✅ Acelera a recuperação → Uma vez que o serviço externo volta ao normal, o Circuit Breaker reabre automaticamente.

Ferramentas que implementam Circuit Breaker

🔹 Resilience4j (Java/Spring Boot)
🔹 Polly (.NET)
🔹 Hystrix (Netflix, legado)
🔹 Istio (Kubernetes Service Mesh)

Quando usar o Circuit Breaker?

✔️ Quando um serviço externo pode falhar ou ficar sobrecarregado.
✔️ Quando você precisa evitar falhas em cascata.
✔️ Quando deseja oferecer uma resposta alternativa enquanto um serviço está indisponível.

Ele é frequentemente usado em arquiteturas de microservices para garantir que falhas isoladas não derrubem todo o sistema.
