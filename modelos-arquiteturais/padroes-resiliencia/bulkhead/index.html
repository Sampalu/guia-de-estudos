Bulkhead (Compartimentalização)

Divide os recursos do sistema em compartimentos isolados para evitar que a falha em um serviço afete os demais.
Exemplo: Um servidor pode alocar threads separadas para diferentes tipos de solicitações, garantindo que um pico em uma área não afete outra.
Categories:
  • Cloud

  2 minute read  

O padrão Bulkhead (inspirado nos compartimentos estanques de navios) isola diferentes partes do sistema para evitar que falhas em uma área afetem o funcionamento de outras. Isso melhora a resiliência e evita falhas em cascata.

Como Funciona?

A ideia principal é dividir os recursos (threads, conexões, memória, etc.) em compartimentos isolados para diferentes tipos de operações ou serviços. Se um compartimento falha, os outros continuam funcionando normalmente.

Exemplo de Uso

Suponha que um sistema tenha três tipos de usuários: premium, padrão e gratuito. Se todos os usuários compartilharem os mesmos recursos e houver um pico de acessos dos usuários gratuitos, isso pode afetar negativamente os usuários premium.

Com Bulkhead, podemos alocar recursos separadamente:

  • Usuários premium → 50% dos recursos
  • Usuários padrão → 30% dos recursos
  • Usuários gratuitos → 20% dos recursos

Dessa forma, mesmo que a carga dos usuários gratuitos aumente, os usuários premium não serão afetados.

Implementações Comuns

  1. Isolamento de Threads: Definir pools de threads separados para diferentes serviços ou tipos de requisições.

    • Exemplo: Um sistema de e-commerce pode ter um pool de threads para processamento de pagamentos e outro para buscas no catálogo.

  2. Isolamento de Conexões: Separar conexões com o banco de dados para evitar que consultas lentas impactem operações críticas.

    • Exemplo: Um microserviço de relatórios pode usar um pool de conexões separado para não impactar a API principal.

  3. Isolamento de Serviços: Criar instâncias dedicadas de um serviço para diferentes grupos de usuários.

    • Exemplo: AWS Lambda pode ser configurado para escalar de forma independente diferentes funções.

Benefícios do Bulkhead

✅ Evita falhas em cascata → Uma sobrecarga em uma parte do sistema não derruba o serviço todo.
✅ Garante previsibilidade → Cada parte do sistema tem recursos garantidos, evitando que um único tipo de requisição consuma tudo.
✅ Melhora a escalabilidade → Facilita distribuir carga e alocar recursos de forma eficiente.

Esse padrão é amplamente usado em sistemas distribuídos e microservices, especialmente em arquiteturas baseadas em Kubernetes e Orquestração de Containers.
