Timeout (Tempo Limite)

Define um limite de tempo para operações, evitando que chamadas bloqueiem indefinidamente um sistema.
Exemplo: Um serviço de API pode cancelar uma requisição que demora mais de 5 segundos.
Categories:
  • Cloud

  2 minute read  

O Timeout é um padrão de resiliência que define um tempo máximo para a execução de uma operação. Se a operação não for concluída dentro desse tempo, ela é cancelada e tratada como uma falha.

Por que usar Timeout?
✅ Evita requisições presas indefinidamente → Se um serviço externo estiver lento ou indisponível, o sistema não fica bloqueado esperando uma resposta.
✅ Melhora a experiência do usuário → Em vez de esperar indefinidamente, o sistema retorna uma falha controlada e pode tentar uma solução alternativa.
✅ Protege recursos do sistema → Evita que conexões fiquem abertas por muito tempo, liberando memória e threads para outras requisições.

Como funciona o Timeout?

Exemplo:

  • Um serviço precisa chamar uma API externa.
  • Define-se um timeout de 3 segundos.
  • Se a API não responder nesse tempo, a requisição é cancelada e o sistema retorna um erro.

Estratégias de Timeout

1️⃣ Timeout Fixo

  • Define um tempo limite fixo para todas as operações.
  • Exemplo: Sempre esperar 2 segundos antes de cancelar.
  • Problema: Pode ser muito curto (causando falhas desnecessárias) ou muito longo (deixando o sistema preso esperando).

2️⃣ Timeout Adaptativo

  • Ajusta o tempo limite com base no desempenho histórico do serviço.
  • Exemplo: Se uma API geralmente responde em 500ms, define um timeout de 1s; se começa a demorar mais, ajusta o timeout para 2s.

3️⃣ Timeout Dinâmico (com Retry)

  • Se uma operação falhar por timeout, tenta novamente com um tempo maior.
  • Exemplo:
    • Primeira tentativa: Timeout de 1s
    • Segunda tentativa: Timeout de 2s
    • Terceira tentativa: Timeout de 4s

Implementação do Timeout em Diferentes Tecnologias

Java com Resilience4j

TimeoutConfig timeoutConfig = TimeoutConfig.custom()
    .timeoutDuration(Duration.ofSeconds(3)) // Timeout de 3 segundos
    .build();

Timeout timeout = Timeout.of("apiTimeout", timeoutConfig);

Node.js com Axios

const axios = require('axios');

axios.get('https://api.exemplo.com/data', { timeout: 3000 }) // 3 segundos
  .then(response => console.log(response.data))
  .catch(error => console.log("Erro por timeout"));

.NET com Polly

var policy = Policy.TimeoutAsync<HttpResponseMessage>(TimeSpan.FromSeconds(3));

await policy.ExecuteAsync(() => httpClient.GetAsync("https://api.exemplo.com"));

Timeout vs. Rate Limiting vs. Circuit Breaker

PadrãoO que faz?Quando usar?
TimeoutCancela operações demoradasQuando um serviço pode ficar lento ou inativo
Rate LimitingRestringe a quantidade de requisiçõesPara evitar sobrecarga e abusos
Circuit BreakerBloqueia chamadas para serviços falhando repetidamentePara evitar falhas em cascata

Melhor prática: Usar Timeout + Retry + Circuit Breaker para um sistema realmente resiliente.

Conclusão

O Timeout é essencial para evitar bloqueios no sistema por operações lentas. Ele melhora a estabilidade, experiência do usuário e eficiência do sistema, especialmente quando combinado com Retry e Circuit Breaker.
