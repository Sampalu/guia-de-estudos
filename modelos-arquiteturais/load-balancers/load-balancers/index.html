Load Balancers e Proxy Reverso

Ao trabalhar com arquiteturas distribuídas e aplicações web escaláveis, dois conceitos fundamentais são Load Balancers (balanceadores de carga) e Reverse Proxy (proxy reverso). Ferramentas como Nginx e HAProxy são amplamente utilizadas para essas finalidades. Vamos entender cada um deles e suas diferenças.

Proxy Reverso

Um proxy reverso é um servidor que fica entre os clientes (navegadores, aplicações) e os servidores de backend (onde a aplicação realmente roda). Ele recebe as requisições dos clientes e decide para onde enviá-las, podendo incluir funcionalidades como:

  • Distribuição de tráfego (mas sem ser, necessariamente, um load balancer)
  • Cache de conteúdo para melhorar desempenho
  • Compressão e otimização de resposta
  • Terminação SSL/TLS, reduzindo a carga nos servidores backend
  • Autenticação e segurança, protegendo os servidores de origem

Exemplo: Se você acessa meusite.com, um proxy reverso pode encaminhar sua requisição para diferentes servidores, servindo páginas estáticas diretamente ou repassando para um servidor de aplicação.

✅ Exemplos de Proxy Reverso:

  • Nginx
  • HAProxy
  • Traefik
  • Caddy

Load Balancer (Balanceador de Carga)

Os balanceadores de carga distribuem o tráfego de rede entre vários servidores, evitando sobrecarga e garantindo escalabilidade e alta disponibilidade. Eles podem atuar em diferentes camadas do modelo OSI.

Tipos de Load Balancers por Camada

  1. Layer 4 Load Balancer (Balanceador de Carga na Camada 4)

    • Opera na Camada de Transporte (TCP/UDP).
    • Redireciona pacotes de rede com base no endereço IP e porta.
    • Não inspeciona o conteúdo dos pacotes, apenas encaminha os dados conforme regras pré-configuradas.
    • Exemplo: HAProxy (modo TCP), IPVS, AWS NLB -Network Load Balancer.

  2. Layer 7 Load Balancer (Balanceador de Carga na Camada 7)

    • Opera na Camada de Aplicação (HTTP/HTTPS).
    • Pode tomar decisões mais inteligentes, baseadas no conteúdo da requisição (ex: headers, cookies, URL, etc.).
    • Permite redirecionamento baseado em regras, como direcionar tráfego de /videos para um servidor especializado e /images para outro.
    • Exemplo: Nginx, HAProxy, Envoy e AWS ALB - Application Load Balancer.

Comparação: NLB vs ALB (Camada 4 vs Camada 7)

CaracterísticaNLB (Camada 4)ALB (Camada 7)
Camada OSICamada 4 (Transporte)Camada 7 (Aplicação)
ProtocolosTCP, UDPHTTP, HTTPS
Análise de Conteúdo❌ Não inspeciona pacotes✅ Pode analisar headers, URLs, cookies, etc.
Performance⚡ Mais rápido (menos processamento)🖥️ Mais pesado (precisa analisar cada requisição)
Redirecionamento🔄 Baseado em IP e porta🎯 Baseado no conteúdo da requisição
Suporte a WebSockets⚠️ Limitado✅ Totalmente suportado
Uso Comum🚀 Aplicações de baixa latência, bancos de dados, VoIP, jogos online🌍 Aplicações web, APIs REST, microsserviços

Quando usar NLB vs ALB?

  • Use um NLB (Layer 4) se:

    • Você precisa de baixa latência (exemplo: jogos online, streaming, VoIP).
    • O tráfego envolve protocolos TCP ou UDP (exemplo: bancos de dados).
    • Quer evitar o overhead do processamento extra da camada 7.

  • Use um ALB (Layer 7) se:

    • Você precisa de roteamento avançado baseado em URL, headers ou cookies.
    • Está lidando com aplicações HTTP/HTTPS, como APIs REST e sites.
    • Deseja usar autenticação e segurança avançada (exemplo: verificação de usuários antes de rotear o tráfego).

Diferença entre Proxy Reverso e Load Balancer

Embora ambos lidem com o tráfego de entrada e encaminhem requisições, há uma diferença importante:

CaracterísticaProxy ReversoLoad Balancer
Objetivo principalEncaminhar e proteger requisiçõesDistribuir carga entre múltiplos servidores
Funciona comUm ou mais servidores backendMúltiplos servidores backend
Pode atuar como cache?SimNão
Garante alta disponibilidade?Não necessariamenteSim

Exemplo Prático:

  • Nginx como Proxy Reverso: Pode servir páginas estáticas e encaminhar requisições para backend.
  • HAProxy como Load Balancer: Distribui tráfego entre múltiplas instâncias de backend.
  • Usando os dois juntos: Nginx pode atuar como proxy reverso na frente de um HAProxy, que faz o balanceamento de carga.

Nginx vs. HAProxy

CaracterísticaNginxHAProxy
Função principalProxy reverso + balanceador de cargaBalanceador de carga
DesempenhoExcelente para servir arquivos estáticos e requisições HTTPExcelente para conexões TCP/HTTP com baixa latência
ConfiguraçãoArquivo de configuração baseado em blocosConfiguração baseada em seções
Recursos avançadosCache, compressão, reescrita de URL, SSLBalanceamento avançado, detecção de falhas, métricas detalhadas

✅ Quando usar o quê?

  • Se precisar apenas de um proxy reverso: Nginx é uma ótima escolha.
  • Se precisar de um balanceador de carga robusto: HAProxy é mais eficiente.
  • Se quiser ambos: Use HAProxy para balanceamento e Nginx para servir conteúdo estático.

Conclusão

  • Proxy reverso atua como um intermediário para proteger e otimizar requisições.
  • Load balancer distribui requisições entre servidores para evitar sobrecarga.
  • Nginx pode ser usado como ambos, mas brilha como proxy reverso.
  • HAProxy é especializado em balanceamento de carga, sendo muito eficiente para alta disponibilidade.

Se você está montando uma arquitetura escalável, pode usar HAProxy para balanceamento e Nginx como proxy reverso e servidor de conteúdo estático.
