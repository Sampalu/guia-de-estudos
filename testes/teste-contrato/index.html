Teste de Contrato (Contract Testing)

O Teste de Contrato é uma técnica que verifica se dois sistemas ou componentes interagem corretamente, garantindo que o contrato estabelecido entre eles seja respeitado. Ele é muito usado em arquiteturas baseadas em microsserviços e APIs.
Categories:
  • Testes

  3 minute read  

Como Funciona?

  • Um contrato define o que um serviço (ex.: API) deve fornecer e como um consumidor (ex.: outro serviço) deve utilizar essa informação.
  • Os testes de contrato garantem que tanto o produtor quanto o consumidor sigam esse contrato, evitando quebras inesperadas.

Fluxo do Teste de Contrato

1️⃣ O consumidor (quem consome o serviço) define um contrato com suas expectativas.
2️⃣ O produtor (quem fornece o serviço) deve garantir que suas respostas seguem esse contrato.
3️⃣ O teste de contrato valida que essa comunicação funciona corretamente.

Benefícios dos Testes de Contrato

✅ Evita quebra de integração → Mudanças em um serviço não afetam outros inesperadamente.
✅ Reduz necessidade de ambientes de teste completos → Simula interações sem precisar da aplicação inteira rodando.
✅ Facilita desenvolvimento paralelo → Consumidores e produtores podem ser desenvolvidos e testados independentemente.
✅ Mais rápido que testes de integração completos → Como testa apenas a interface de comunicação, é mais leve e rápido.

Tipos de Testes de Contrato

1️⃣ Testes Baseados em Schema

  • Verificam se as respostas seguem o formato esperado.
  • Exemplo: Uma API REST deve sempre retornar um objeto JSON com certas chaves e tipos de dados.
  • Ferramentas: JSON Schema, OpenAPI Validator.

🔹 Exemplo em JSON Schema

{
  "type": "object",
  "properties": {
    "id": { "type": "integer" },
    "nome": { "type": "string" },
    "idade": { "type": "integer" }
  },
  "required": ["id", "nome"]
}

Se uma API retorna { "id": 1, "nome": "Carlos" }, o contrato é válido.
Mas se retorna { "id": "ABC", "nome": "Carlos" }, o teste falha (pois id deveria ser um número).

2️⃣ Testes de Contrato Consumidor-Produtor (Pact Testing)

  • O consumidor define um contrato com expectativas sobre o serviço.
  • O produtor valida se cumpre esse contrato antes de lançar mudanças.
  • Ferramentas: Pact, Spring Cloud Contract.

🔹 Exemplo com Pact (JavaScript)
Consumidor define o contrato esperado:

const provider = pact({
  consumer: "AppCliente",
  provider: "APIUsuarios"
});

provider.addInteraction({
  state: "Usuário existe",
  uponReceiving: "Requisição para obter um usuário",
  withRequest: { method: "GET", path: "/usuarios/1" },
  willRespondWith: {
    status: 200,
    body: { id: 1, nome: "Carlos" }
  }
});

Produtor executa o teste para garantir que sempre fornecerá essa resposta correta.

3️⃣ Testes de Contrato em GraphQL

  • Verificam se consultas e mutações GraphQL seguem o esquema correto.
  • Ferramentas: GraphQL Inspector, Apollo Contracts.

🔹 Exemplo de Schema GraphQL

type Usuario {
  id: ID!
  nome: String!
  email: String!
}

Se a API retorna um usuário sem email, o contrato quebra.

Quando Usar Testes de Contrato?

✅ Em microserviços, para garantir que cada serviço fornece e consome APIs corretamente.
✅ Em integrações entre sistemas, como entre um back-end e um front-end.
✅ Para APIs públicas e internas, garantindo compatibilidade ao longo do tempo.
✅ Em ambientes de CI/CD, para impedir que mudanças quebram consumidores dependentes.

Conclusão

Os Testes de Contrato são essenciais para evitar problemas de integração, garantindo que consumidores e produtores se comuniquem corretamente. Eles reduzem falhas inesperadas, facilitam o desenvolvimento independente e ajudam a manter APIs confiáveis e estáveis.
